## 0. Правила, которые сильнее любого кода (слова врача)
1. **«Я запрещаю давать свои рекомендации без моего канона».** Любое клиническое утверждение идёт из канона или из подписанного документа. Своё — только с пометкой «построено движком, не подписано» и вопросом Р-*.
2. **«Не выдумывать».** Ни данных, ни цифр, ни больных, ни ссылок. «У нас этого нет» — только после поиска по канону и Drive.
3. **`drugbase.json` подписан врачом.** Код в него не пишет никогда. Печать (md5 `99c733f1…`) сторожится тестом.
4. **Канон правится только скриптами `ustanovka/write_canon_*.py`**, чтобы правка была видна и повторяема.
5. **Слой L1 видит только подписывающий врач** (claim `litvak`). Наружу — только конвенциональный слой после стража (grep стоп-слов = 0).
6. **Тесты врача не переписываются**, если в них закодировано клиническое решение. Учётное число поправить можно, но сказав вслух.
7. **Данные больных в пакет разработчика не идут.** Случаи — по идентификатору. Имена и даты рождения не попадают ни в тесты, ни в канон.

## 2. Как собрать и проверить (без облака, ~10 минут)
```bash
cd 01_CODE/metacod-omer-app
npm install                                  # Node 20–22; ставит client и server (workspaces)
bash shared/engines/__tests__/run.sh         # ждём: 0 FAIL (на 01.10 — 4706 OK)
cd server && npm run build && npm run verify # tsc + SKILL.md в lib/ + проверка
node smoke_adapter.js                        # ждём 20/20
cd ../client && npx tsc --noEmit             # клиент без ошибок
```
**Сквозной прогон на эмуляторах** (нужны Java и `firebase-tools`):
1. Скопировать `08_CLOUD_CHECKS/firebase.emulators.json` в `server/`.
2. Запустить: `firebase emulators:start --config firebase.emulators.json --project demo-metacod --only auth,firestore,functions`.
3. Запустить прогон: `node e2e_emulators.js <путь к metacod-omer-app> <тестовый service-account.json>`. Ждём 30/30.

## 3. Как выйти в облако
1. **Проект Firebase** (например, `metacod-omer`), Web-app. Регион Firestore — **europe-west1**. Включить Auth (Email/Password) и Firestore (production).
2. Выполнить `firebase use <проект>` (создаст `.firebaserc`).
3. **Клиент:** `client/.env` по образцу `client/.env.example`:
   - `EXPO_PUBLIC_FIREBASE_API_KEY`;
   - `EXPO_PUBLIC_FIREBASE_APP_ID`;
   - по желанию `PROJECT_ID` и `AUTH_DOMAIN`.
4. **Ключ модели:** `firebase functions:secrets:set ANTHROPIC_API_KEY`. Если нужно, задать `ANTHROPIC_MODEL` и `CONSENT_TEXT_VERSION` в `server/.env`.
   - ⛔ Без ключа модели разбор пуст и законно блокируется контуром §4У·1: работы не будет.
5. **Выкладка:** `cd server && npm run deploy`. Сборка, проверка `lib/`, функции, правила и индексы — одной командой.
6. **Роли:** каждый врач один раз входит в приложение. Затем `GOOGLE_APPLICATION_CREDENTIALS=… node tools/назначить_роль.js <почта> doctor|litvak`, и врач выходит и входит заново.
7. **Проверка ключей:** `bash tools/проверить_ключи.sh` → «ГОТОВО К ЗАПУСКУ».
8. **Дымовой прогон:** пройти `ПЕРВЫЙ_ДЕНЬ_В_ОБЛАКЕ.md` целиком, **до** первого живого больного.

⛔ Служебный ключ, `.env` и `*.pem` в репозиторий и мессенджеры не класть. `.gitignore` это закрывает.
⛔ Бинарные архивы на Drive не загружать: был случай порчи.
